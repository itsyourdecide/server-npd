## Главный принцип

Сегодня не ломать уже работающий удалённый доступ к `pve01`.

Значит:

- текущий доступ к `pve01` через лабораторную сеть и Tailscale сохраняется;
- `vmbr0` не трогаем как основной внешний uplink;
- внутреннюю сеть поднимаем отдельно;
- только после запуска `OPNsense` начинаем переключать логику на VLAN/switch.

## Результат, который хотим получить к концу дня

- `pve01` доступен по Tailscale и через web UI;
- ISO `OPNsense` загружен в Proxmox;
- создана VM `fw01` с `OPNsense`;
- у `fw01` есть минимум два интерфейса:
  - `WAN` в лабораторную сеть;
  - `LAN` во внутренний bridge;
- поднят отдельный внутренний bridge на `pve01`;
- `OPNsense` раздаёт DHCP в тестовую внутреннюю сеть;
- тестовая VM получает IP через `OPNsense` и выходит в интернет;
- зафиксированы все изменения в `cluster_operations_log.md`.

## Этап 2. Подготовить внутреннюю сеть на `pve01`

Задача: создать отдельный bridge для LAN-стороны `OPNsense`, не затрагивая текущий uplink.

- [ ] Оставить `vmbr0` как внешний/лабораторный uplink.
- [ ] Создать новый bridge, например `vmbr1`.
- [ ] `vmbr1` сначала создать без физического порта.
- [ ] Не назначать `vmbr1` IP на хосте, если он нужен только как внутренний сегмент для VM.

Ожидаемый смысл:

- `vmbr0` = внешний WAN путь;
- `vmbr1` = внутренняя сеть для OPNsense LAN и тестовых VM.

## Этап 3. Скачать OPNsense ISO

- [ ] Скачать актуальный ISO `OPNsense` на `pve01` или сразу через Proxmox UI.
- [ ] Проверить checksum, если удобно.
- [ ] Загрузить ISO в storage Proxmox (`local` / ISO Images).
- [ ] Зафиксировать версию ISO в журнале.

## Этап 4. Создать VM `fw01`

Рекомендуемые стартовые параметры:

- имя: `fw01`
- ОС: `OPNsense`
- vCPU: `2`
- RAM: `4 GB`
- disk: `20–32 GB`
- autostart: `on`

Сетевые интерфейсы:

- NIC1 -> `vmbr0` = `WAN`
- NIC2 -> `vmbr1` = `LAN`

Если будет удобно, можно сразу выбрать `VirtIO` NIC, но если вдруг будут странности на установке, временно допустим `E1000`.

## Этап 5. Установить и первично настроить OPNsense

Минимальная целевая конфигурация на сегодня:

- `WAN` = DHCP от лабораторной сети
- `LAN` = статический адрес

Для первого теста проще всего:

- `LAN IP`: `10.10.40.1/24`

Почему не весь management VLAN сразу:

- сначала нужен безопасный минимальный тест NAT/DHCP;
- потом легче масштабировать на VLAN 10/30/40/50/80.

После установки:

- [ ] войти в web UI OPNsense;
- [ ] проверить, что `WAN` получил адрес;
- [ ] назначить `LAN` адрес;
- [ ] включить DHCP на `LAN`, например диапазон `10.10.40.100-10.10.40.199`;
- [ ] убедиться, что outbound NAT работает.

## Этап 6. Поднять тестовую VM за OPNsense

- [ ] Создать маленькую тестовую Linux VM.
- [ ] Подключить её только к `vmbr1`.
- [ ] Убедиться, что она получила адрес по DHCP от `OPNsense`.
- [ ] Проверить ping до `10.10.40.1`.
- [ ] Проверить выход в интернет.
- [ ] Проверить DNS.

Успех этого этапа означает, что базовая схема router VM уже работает.
