## Главный принцип

Не включать все 4 узла одновременно (пусковой ток, см. `cluster_power_thermal_priority.md` §7) и не спешить с полноценным вводом в HTCondor — сегодняшняя цель узкая: понять, что это за железо и может ли BMC делить порт с LAN.

## Этап 1 — физическое подключение и осмотр

- [ ] Запитать шасси (проверить розетку/PDU, не превышает ли пусковой ток доступное).
- [ ] Сфотографировать переднюю/заднюю панель, шильдик модели/серийника шасси и каждого узла.
- [ ] Определить точную модель: `RS720QA` (без InfiniBand) или `RS724QA` (со встроенным ConnectX-2 QDR) — по факту может быть смесь.
- [ ] Найти на задней панели: сетевые порты (сколько на узел — обычно минимум 1 LAN + возможно выделенный BMC), разъём консоли/VGA, если есть.
- [ ] **Не включать все узлы сразу** — включить только **узел 1**.

## Этап 2 — первый узел: консоль и BIOS

Сеть ещё не подключена, поэтому доступ к консоли — только напрямую (VGA+клавиатура/крэш-карт), как раньше со свитчом через serial.

- [ ] Подключить монитор+клавиатуру к узлу 1, зайти в BIOS/POST.
- [ ] Найти в BIOS секцию IPMI/BMC (обычно `IPMI Configuration` или аналог в Advanced/Server Mgmt).
- [ ] **Главный вопрос сегодня**: найти настройку режима LAN-интерфейса BMC — обычно называется `LAN Interface`, `NCSI`, `Shared/Dedicated LAN`. Зафиксировать, какие режимы доступны и что выбрано сейчас.
- [ ] Записать текущий BMC IP (если задан статически) или режим (DHCP/статика).
- [ ] Проверить версию BIOS/BMC, если видно в этом же меню.

## Этап 3 — сеть: подключить узел 1 к switch1

Пока не важно, в какой именно порт — берём любой свободный порт для теста (например 19, по `production_port_plan.md` это первый порт под ASUS-LAN). VLAN на нём сейчас по умолчанию untagged VLAN10 (MGMT) — этого достаточно, чтобы просто получить связь и опросить узел; на правильный VLAN80/30 переведём после того, как поймём схему Shared LAN.

- [ ] Кабель LAN узла 1 → порт 19 switch1.
- [ ] Если у узла отдельный физический BMC-порт — второй кабель в соседний свободный порт (например 20), тоже пока VLAN10.
- [ ] С `pve01` (он уже в VLAN10 через транк) проверить связность: если BMC/OS получили адрес по DHCP — его не будет (DHCP только в VLAN40/80 на fw01, не в VLAN10) — вероятно, доступ будет только если задать временный статический IP на BMC вручную, как делали для IPMI pve01.

## Этап 4 — инвентаризация узла 1 (`cluster_inventory_checklist.md` §6)

Как только появится хоть какой-то доступ (консоль или сеть):

```bash
lscpu
free -h
lspci -nnk
ip -br link
sudo ipmitool mc info
sudo ipmitool sensor list
```

- [ ] Заполнить строку таблицы: Chassis / Model / Nodes / RS720 или RS724 / IB QDR (да/нет) / BMC (модель/прошивка) / PSU status.
- [ ] Возможность PXE boot — уточнить в BIOS boot order, реальный тест PXE не обязателен сегодня.
- [ ] Если время останется — повторить для узлов 2-4 (уже быстрее, раз путь понятен).
