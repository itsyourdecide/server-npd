# ADR-0001: Proxmox VE на серверах Supermicro

Статус: accepted
Дата решения: 2026-07-01
Последняя редакция: 2026-09-05
Источник истины для: выбора платформы виртуализации Supermicro

## Контекст

Кластер должен предоставлять персональные и инфраструктурные VM/LXC,
миграцию, единое управление и возможность использовать свободные CPU/RAM для
batch-вычислений. Эксплуатацией занимается небольшая команда, поэтому сложный
отдельный cloud control plane нежелателен.

Имеется до десяти серверов Supermicro. Первые три уже образуют кластер
`pve01`–`pve03`.

## Рассмотренные варианты

### Bare-metal Linux на всех Supermicro

Проще для HPC, но не закрывает удобное управление VM, миграции и единые
инфраструктурные сервисы.

### Proxmox только на трёх core-узлах

Снижает требования к постоянно включённому quorum, но оставляет остальные
серверы вне общей VM-платформы.

### OpenStack

Даёт развитый private cloud, но создаёт несоразмерный текущему масштабу control
plane и эксплуатационную нагрузку.

### Proxmox на проверенных Supermicro

Даёт KVM, LXC, cluster management, replication и HA-механизмы в одной
платформе. Узлы можно вводить постепенно после проверки оборудования и
инженерной инфраструктуры.

## Решение

Использовать Proxmox VE как базовую платформу Supermicro.

- Действующий кластер: `pve01`–`pve03`, имя `npd`.
- Новые Supermicro добавляются по одному после inventory, network,
  power/thermal и quorum review.
- Batch software не устанавливается в Proxmox host OS; для этого используются
  отдельные execute VM.
- Критические сервисы получают отдельные recovery/backup решения, а наличие
  Proxmox-кластера само по себе не считается HA.

## Последствия

Плюсы:

- единое управление VM/LXC и сетью;
- миграция сервисов при обслуживании;
- возможность гибко выделять ресурсы;
- единый подход к автоматизации.

Ограничения:

- каждый добавленный голос влияет на quorum и требования к доступности;
- старое оборудование нельзя массово вводить без burn-in;
- PVE-узлы нельзя использовать в ASUS power-saving automation;
- для настоящей HA нужны fencing, доступное хранилище, backup и испытания.

## Условия пересмотра

- электрика или охлаждение не позволяют поддерживать выбранное число PVE-узлов;
- реальная потребность в VM значительно ниже ожидаемой;
- возраст оборудования делает большой единый кластер нестабильным;
- сопровождение Proxmox перестаёт соответствовать ресурсам команды.
