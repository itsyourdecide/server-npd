# Проверка здоровья кластера

- Статус: current
- Последняя проверка процедуры: 2026-09-05
- Last tested: 2026-08-13
- Назначение: единая безопасная проверка основных компонентов без изменения инфраструктуры
- Источник истины для: порядка запуска и трактовки cluster health-check

## Воздействие

Проверка только читает состояние Proxmox, LXC/VM, HTCondor, PXE, Squid,
monitoring, DNS и storage. Планового простоя нет. Запускать с `pve01` или с
административного хоста, где доступны те же SSH-ключи и Ansible inventory.

## Предпосылки

- есть административный SSH-доступ к `pve02` и AlmaLinux-узлам;
- заполнен `ansible/inventory/hosts.yml`;
- известен текущий режим JBOD/NFS;
- работа выполняется не во время незавершённого failover или физической
  перекоммутации.

## Процедура

Из корня репозитория:

```bash
./scripts/cluster-health.sh
```

Если JBOD намеренно отключён и это отражено в
[open issues](../project/open-issues.md), допускается:

```bash
./scripts/cluster-health.sh --skip-storage
```

Для отдельных подсистем:

```bash
./scripts/monitoring-health.sh
./scripts/storage-smoke.sh
```

`storage-smoke.sh` не запускать, если storage помечен как offline или его
состояние неизвестно.

## Стоп-критерии

- потерян quorum Proxmox;
- недоступен административный SSH-путь;
- обнаружена незавершённая миграция `fw01`;
- storage неожиданно импортирован на нескольких узлах;
- команда запрашивает пароль или интерактивное изменение конфигурации.

## Результат и фиксация

Успешный запуск завершается без `FAIL`. `SKIP storage` является допустимым
только при документированной причине и не доказывает исправность storage.

После проверки:

1. обновить дату только у действительно проверенных компонентов в
   [current state](../current-state.md);
2. для каждого нового сбоя создать или обновить задачу в
   [open issues](../project/open-issues.md);
3. результат изменения состояния записать в журнал текущего месяца.

Rollback не требуется: процедура не меняет конфигурацию.
